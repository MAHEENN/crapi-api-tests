# SEC-002 — Information Disclosure in API Validation Responses

## Finding Summary

- **Severity:** Low (provisional)
- **Classification:** CWE-209 — Generation of Error Message Containing Sensitive Information
- **Endpoint:** POST /identity/api/v2/vehicle/add_vehicle
- **Component:** Identity Service
- **Status:** Confirmed — remediation pending
- **Environment:** Local crAPI test environment

## Description

The API returns internal Spring validation diagnostics and rejected input values when request validation fails.

## Root Cause

The `handleMethodArgumentNotValid()` method in `ExceptionHandler.java` converts the Spring BindingResult object into a string and includes it directly in the API error response.

```java
String bindingResult = ex.getBindingResult().toString();
ErrorDetails errorDetails =
    new ErrorDetails("Validation failed", bindingResult);
```

The application does not sanitise the validation diagnostics before returning them to the client.

## Confirmed Evidence

The automated security regression confirmed three information disclosures:

- Rejected synthetic PIN value.
- Internal Spring validation class information.
- Internal framework package information.

The API correctly returned HTTP 400, but all three confidentiality assertions failed.

## Security Impact

The response unnecessarily exposes implementation details and potentially sensitive user-supplied values. Such information could assist application reconnaissance or be retained in downstream response logs.

No broader data exposure or account compromise has been established.

## Recommended Remediation

- Return sanitised, user-friendly validation messages.
- Exclude rejected sensitive input values.
- Exclude internal framework diagnostics and class names.
- Define an approved validation error response schema.
- Preserve HTTP 400 for invalid requests.

## Automated Regression Coverage

Test file: `tests/api/vehicle-security.spec.ts`

The regression verifies that validation responses do not disclose rejected input or known internal framework diagnostics.

**Current result:** Failed as expected against the vulnerable implementation.
