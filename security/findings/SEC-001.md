# SEC-001 — Account enumeration through login error messages

| Field | Finding |
| --- | --- |
| Environment | Local crAPI QA lab |
| Endpoint | `POST /identity/api/auth/login` |
| Classification | Provisional [CWE-204 — Observable Response Discrepancy](https://cwe.mitre.org/data/definitions/204.html) |
| Status | Observed in the recorded QA session. Fix verification pending. |

## Summary

The local crAPI login endpoint returned different error messages for an unregistered email and a registered account with an incorrect password. The message reveals whether the email is associated with an account before authentication succeeds.

## Reproduction record and evidence

The recorded Burp Repeater comparison covered two failed login cases on the same local endpoint. The cases represented an email absent from the lab and an existing lab account with an incorrect password.

| Lab case | HTTP status | Observed response message |
| --- | --- | --- |
| Unregistered email | `401` | `Given Email is not registered!` |
| Registered account with incorrect password | Unrecorded | `Invalid Credentials` |

The Playwright test failed when it compared the two response messages for equality. This corroborates the message discrepancy observed in Burp Repeater. Both cases should return the same public authentication error.

## Impact

The response discloses account membership for an email address to an unauthenticated caller. Where account membership is sensitive, that disclosure has a privacy impact on its own. It could also help a caller target phishing or credential-stuffing attempts toward known accounts.

## Remediation

Return a consistent public failure response for both cases, using HTTP `401` and the same generic message, such as `Invalid email or password`. Use the same response body structure, public error code, and relevant headers. Record diagnostic distinctions only in appropriately restricted server-side logs and exclude passwords. Review whether the two failure paths expose measurable timing differences.

## Fix verification

- Rerun the existing Playwright regression against the patched local build with lab fixtures. Assert that both cases return `401` and the agreed generic message. Checking the expected values as well as equality guards against a false pass if both cases return an unrelated error.
- Compare both responses in Burp Repeater to verify consistency in the public error code, body structure, and relevant headers. Confirm that successful login still works in the lab.
- Record the tested build, the regression result, and any remaining differences.

## Limitations

The evidence is limited to the local QA session. The source record supplies the status for the unregistered-email case only. The crAPI build, response headers, timing, rate limiting, and behavior outside the local lab are unverified. The observed impact is account membership disclosure. Account access was outside the test scope.
